Final MVP Scope (Multi-Tenant SaaS)
1. Authentication & Multi-Tenancy

Shop owners (admins) can sign up / log in.

Each shop’s data is logically isolated (multi-tenant DB design).

Super-admin (our side) has access to manage tenants if required (future consideration).

2. Shop Owner / Admin Features

Configure menu items (CRUD for food/drinks).

Configure tables (each table gets a unique QR code endpoint → customers scan).

View all sessions (sessions = multiple orders until paid).

Track orders (per session → grouped under a table).

Cancel/reject orders (if customer places by mistake or unavailable item).

Mark session as Paid / Unpaid (when payment is settled offline).

See payment info in session:

Session total amount.

Paid/Unpaid status.

Table number.

Orders under session.

3. Customer Features (via QR scan)

Scan QR → open table-specific page (React Native WebView or mobile).

Browse menu items.

Place orders (added into current session for that table).

View their current session (see all placed items until paid).

No login required for customers.

4. Sessions & Orders

Session = all orders for a table until marked “paid.”

Each order belongs to a session (linked to table).

Order status: Placed → Accepted → Served (basic flow).

Orders can be canceled/rejected by admin/cook side only.

5. Payments

For MVP: Payment handled offline (cash/card at restaurant).

Store payment info in session:

Total bill amount.

Paid/Unpaid flag.

Time of settlement (optional).

6. Non-MVP (Phase 2 / Nice-to-Have)

Notifications (new order alerts for admin).

Reporting (sales summary, popular items, table turnover).

Staff logins (waiters/cooks).

Online payments integration.
